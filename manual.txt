Visão geral da Api de Cobrança


    Introdução
Este manual descreve como integrar e utilizar a API de Cobrança Bradesco, que permite a geração,
consulta e gestão de cobranças de forma automática e segura.

A API foi desenvolvida para facilitar a integração entre sistemas, possibilitando a emissão de cobranças,
acompanhamento de status e controle do ciclo de pagamento por meio de requisições padronizadas.
Este documento é destinado a desenvolvedores e equipes técnicas responsáveis pela integração e
manutenção dessa solução.

   Aviso importante, os pré-requisitos mencionados a esses produtos, são correspondentes a
contratação do plano de produção.




    Pré-requisitos
1. Possuir Contrato de Cobrança Bradesco ativo;

2. Solicitar ao gerente do banco a habilitação da funcionalidade “175 – Registro via Webservice”.

3. Ter acesso habilitado ao Bradesco Net Empresa.

4. Desenvolver a conectividade conforme descrito neste manual, integrada ao sistema de geração e
   emissão de boletos de cobrança.

   Clientes que possuam Contrato de Cobrança Bradesco ativo, mas que ainda não tenham
   realizado o primeiro acesso ao Bradesco Net Empresa, devem efetuá-lo antes de realizar o
   registro de boletos por esta sistemática.

Esse acesso inicial é obrigatório para que o cliente seja reconhecido e autenticado na Plataforma
Bradesco, permitindo a utilização do serviço de registro via Webservice.




    Público-alvo
A API de Cobrança Bradesco é destinada a empresas de todos os setores, como indústrias, comércios,
prestadoras de serviços e agronegócios, que necessitam automatizar seus processos de recebimento.

Também podem utilizar a solução órgãos governamentais de qualquer esfera — municipal, estadual ou
federal — tanto da administração direta quanto indireta.

Além disso, profissionais liberais, produtores rurais e trabalhadores autônomos que precisam receber
pagamentos por ofertas, propostas, vendas ou serviços prestados encontram nessa solução uma opção
eficiente e segura.




    Funcionalidades

   Registro de boleto on-line

O registro de boleto de cobrança é uma solução destinada a empresas que necessitam gerar e registrar
boletos de forma ágil, prática e segura, diretamente via API.

Essa abordagem elimina a necessidade de acesso ao NET EMPRESA por meio de interface própria,
permitindo total automação do processo, maior eficiência operacional e integração direta com os
sistemas do cliente.


   Consulta de título específico e 2ª via

Para aprimorar a experiência no produto Cobrança, disponibilizamos a API de Consulta de Título, que
permite a visualização detalhada das informações de um título registrado.
Os dados são apresentados de forma atualizada e, a partir do resultado dessa consulta, é possível gerar
a 2ª via do boleto, proporcionando mais praticidade, autonomia e agilidade na gestão dos registros.


   Consulta de títulos liquidados

A funcionalidade permite a consulta, via API, dos títulos de cobrança liquidados, proporcionando uma
visão consolidada e atualizada das liquidações realizadas. Com isso, o cliente obtém maior controle e
eficiência na gestão da carteira de Cobrança, facilitando a conciliação financeira e o acompanhamento
dos recebimentos.


   Consulta de títulos baixados (cancelados) por lista

A funcionalidade permite a consulta, via API, dos títulos de cobrança baixados (cancelados), oferecendo
uma visão atualizada dos registros encerrados. Essa consulta contribui para uma melhor gestão da
carteira de Cobrança, auxiliando no controle operacional, na conciliação e no acompanhamento do ciclo
de vida dos títulos.


   Consulta de título pendente de Pagamento

A API de Consulta de Títulos Pendentes permite consultar os títulos de cobrança ativos, oferecendo uma
visão atualizada das pendências em aberto.
Essa funcionalidade proporciona maior controle e eficiência na gestão da carteira de cobrança, apoiando
o acompanhamento dos recebíveis e a tomada de decisões.


   Alteração de boleto

Para aprimorar a experiência no produto Cobrança, disponibilizamos a API de Alteração de Títulos, que
permite realizar a manutenção de títulos registrados diretamente na base de cobrança.
Com essa funcionalidade, o cliente pode efetuar alterações de forma ágil, prática e segura, garantindo
maior autonomia, eficiência operacional e integração com seus sistemas internos.


   Baixa do boleto (Cancelamento)

A API de Baixa de Título permite realizar a solicitação de baixa (cancelamento) de um título específico
diretamente via API, desde que o título esteja registrado na base de cobrança.
Essa funcionalidade proporciona maior agilidade, controle operacional e automação do processo,
eliminando a necessidade de utilização de outros canais para encerramento do título.


   Webhook (notificação instantânea de boletos pagos)

O webhook é um sistema de troca de mensagens de uma aplicação para outra em tempo real, sempre
que um evento específico acontece. Pense nele como uma “notificação automática” ou um “aviso
instantâneo” entre sistemas.

Webhooks eliminam a necessidade de os clientes realizarem consulta ao Banco a todo momento
(polling), com o Webhook o cliente passa a ser informado na ocorrência de uma liquidação, garantindo
uma melhor performance ao processo. (“Banco do Brasil”)




   Split de Cobrança (Rateio de Crédito)

A API de Manutenção de Split Payment (Rateio de Crédito) centraliza todas as operações relacionadas
ao rateio de valores, permitindo sua gestão de forma ágil, prática e segura.

Com essa funcionalidade, o cliente pode realizar manutenções diretamente via API, eliminando a
necessidade de utilizar outros canais e garantindo maior eficiência operacional, automação e controle
do processo.


   Protesto e Negativação

A API possibilita que o cliente realize o Protesto e Sustação de Protesto via API, permitindo gerar
comandos nos títulos registrados, sem a necessidade de utilizar outros canais.




Registo de boleto via API
A API de registro de boleto de Cobrança é uma solução voltada para as empresas que necessitam gerar
seu boleto de Cobrança de forma ágil, prática e segura, sem a necessidade de acessar o NET EMPRESA
através de uma interface própria.

Layout de Desenvolvimento

O exemplo apresentado abaixo tem caráter meramente ilustrativo, sendo utilizado exclusivamente
como referência para a formatação dos campos.

Observações para o preenchimento dos campos:

1. Todos os campos devem ser informados conforme definido no layout.
   Para os campos não obrigatórios, o preenchimento deve seguir os critérios abaixo:

          o   Campos numéricos: preencher com zero (0);
          o   Campos alfanuméricos: preencher com espaços ou deixar em branco, conforme
              especificado.
          o   Formato de preenchimento de Campos Alfanumérico:
                    Permitidos: letras de A–Z/a–z, números 0–9, espaço.
                    Não permitido: ., -, /,á, é, í, ó, ú, ã, â, ç, ! @ # % & * etc.

2. Nos campos relacionados a multa, juros, bonificação ou desconto, deve ser informado apenas
   valor ou percentual, nunca ambos simultaneamente.

3. A formatação de campos percentuais na API deve conter 2 dígitos inteiros e 3 casas decimais,
   conforme os exemplos abaixo:


                Preenchimento na API
  (%)
  0,5           0.5
  10            10 ou 10.00
  12,12         12.12

4. Para utilização do campo Decurso de Prazo – tipoPrazoDecursoTres na requisição, é necessário que
o indicador correspondente no Contrato de Cobrança esteja cadastrado com o valor ZERO.




Regras de cálculo dos encargos

Juros - Os juros correspondem ao valor cobrado diariamente após o vencimento.

Cálculo do juro diário:

Valor do título × % de juros mensal / 30 = Juros diário (em R$)


Desconto - Valor fixo concedido como redução no boleto até a data de vencimento.


Abatimento - Valor fixo concedido como redução durante toda a vida do título, independentemente da
data de vencimento.


Bonificação - Representa uma redução diária no valor do título até o vencimento, sendo o inverso do
conceito de juros.

Exemplo:

Título emitido em 01/04, com vencimento em 20/04, com bonificação de R$ 1,00 por dia:

Pagamento em 01/04 → bonificação total de R$ 20,00.

Caso seja percentual, por exemplo 1% ao dia, o pagamento em 01/04 resultaria em 20% de bonificação
Multa -
A multa é cobrada apenas uma vez, após o vencimento, e sempre em percentual sobre o valor do título.

Exemplo de cálculo:

Valor do boleto: R$ 100,00
Multa: 10%
Valor da multa: R$ 10,00

Linha digitável:

É composta por cinco campos:


1º Campo: composto pelo código do Banco, código da moeda, as cinco primeiras posições do campo
livre e o dígito verificador desse campo.

"2º Campo: composto pelas posições 6ª a 15ª do campo livre e o dígito verificador desse campo." (“Linha
Digitável e Código de Barras Bradesco”)

"3º Campo: composto pelas posições 16ª a 25ª do campo livre e o dígito verificador desse campo."
(“Linha Digitável e Código de Barras Bradesco”)

"4º Campo: composto pelo dígito verificador do código de barras, ou seja, a 5ª posição do código de
barras." (“Linha Digitável e Código de Barras Bradesco”)

5º Campo: composto pelo fator de vencimento com 4 (quatro) caracteres e o valor do documento com
10 (dez) caracteres, sem separadores e sem edição.


Entre cada campo deverá haver espaço equivalente a 2 (duas) posições, sendo a 1ª interpretada por um
ponto (.) e a 2ª por um espaço em branco.

API de Baixa de Título
A API de Baixa de Título permite realizar a solicitação de baixa (cancelamento) de um título específico
diretamente via API, desde que o título esteja registrado na base de cobrança.

Essa funcionalidade proporciona maior agilidade, controle operacional e automação do processo,
eliminando a necessidade de utilização de outros canais para encerramento do título.


Realizar requisição conforme abaixo:

 URL                      Método      Endpoint
                                      https://openapisandbox.prebanco.com.br/boleto/cobranca-
 Sandbox                  POST
                                      baixa/v1/baixar
                                      https://openapi.bradesco.com.br/boleto/cobranca-
 Produção                 POST
                                      baixa/v1/baixar


A baixa é processada de forma on-line, impedindo o pagamento no Bradesco e em outros Bancos.

Obs.: No período da 00h00 às 03h00 pode haver indisponibilidade de acesso à API face às
atualizações de tabelas e processamento batch.

Alteração de título via API
   Para aprimorar a experiência no produto Cobrança, disponibilizamos a API de Alteração de Títulos, que
   permite realizar a manutenção de títulos registrados diretamente na base de cobrança.

   Com essa funcionalidade, o cliente pode efetuar alterações de forma ágil, prática e segura, garantindo
   maior autonomia, eficiência operacional e integração com seus sistemas internos.


    Ambiente          Método         URL
                                     https://openapisandbox.prebanco.com.br/boleto/cobranca-
    Sandbox           PUT
                                     altera/v1/alterar
                                     https://openapi.bradesco.com.br/boleto/cobranca-
    Produção          PUT
                                     altera/v1/alterar


   Para realizar uma alteração, o usuário deve enviar a requisição contendo todos os dados do boleto,
   informando apenas os campos que deseja modificar (por exemplo: desconto, juros, entre outros).

   A Plataforma Bradesco realizará a validação das informações recebidas e, caso estejam corretas,
   retornará os dados do boleto bancário devidamente alterados, com atualização tanto na Plataforma
   Bradesco quanto na CIP, conforme o layout apresentado abaixo.

Consulta lista de títulos liquidados via API
A funcionalidade permite a consulta, via API, dos títulos de cobrança liquidados, fornecendo uma
visão consolidada e atualizada das liquidações realizadas.

Com esta funcionalidade, o cliente obtém maior controle e eficiência na gestão da carteira de
Cobrança, facilitando a conciliação financeira e o acompanhamento dos recebimentos.

Para realizar a consulta, é necessário informar os campos obrigatórios:

•     CPF/CNPJ do Beneficiário
•     Produto (Carteira)
•     Negociação

Além dos campos obrigatórios, podem ser informados parâmetros adicionais de filtragem, conforme
descrito abaixo.
  Parâmetros disponíveis para pesquisa

  •       Data de Movimento – período De/Até (opcional)
  •       Data de Pagamento – período De/Até (opcional)
  •       Tipo de Registro (Origem)* (opcional)
  •       Valor de Pagamento – intervalo De/Até (opcional)


  *Tipo de Registro (Origem):

      Cód. Origem             DESCRIÇÃO
      0                       TODOS
      1                       COM REGISTRO
      2                       SEM REGISTRO
      3                       POR CONTABILIDADE


  É possível realizar a combinação de múltiplos critérios de consulta. Por exemplo, consultar os títulos
  de um determinado CPF/CNPJ, dentro de uma faixa de vencimento específica e limitados a uma faixa
  de valores.

  Quanto maior o número de critérios informados, mais refinado será o resultado da consulta.

  O período máximo de consulta é de 60 dias a partir da data de pagamento, e as informações
  disponibilizadas seguem o conceito D-1 (dados do dia anterior).


  Para efetuar a consulta, realize a requisição conforme descrito abaixo:


      Ambiente         Método         URL

      Sandbox          POST           https://openapisandbox.prebanco.com.br/boleto/cobranca-lista/v1/listar

      Produção         POST           https://openapi.bradesco.com.br/boleto/cobranca-lista/v1/listar



  Obs.: No período da 00h00 às 03h00 pode haver indisponibilidade de acesso à API face às
  atualizações de tabelas e processamento batch.


Observações sobre o preenchimento dos campos

  1. Todos os campos devem ser informados conforme definido no layout.

          Para os campos não obrigatórios, adotar o seguinte padrão:

             o   Campos numéricos: preencher com zero (0);
             o   Campos alfanuméricos: preencher com string vazia ("").


  2. A nomenclatura dos campos é case sensitivo, ou seja, diferencia letras maiúsculas e minúsculas.

          Portanto, os nomes dos campos devem ser informados exatamente conforme descritos no Layout
     de Comunicação e conforme demonstrado no Exemplo de Entrada (JSON) apresentado abaixo.

Nota: A consulta demonstra até 50 registros por chamada. Porém, se a consulta possuir mais
registros, é necessário programar chamadas recorrentes para demonstrar todo o resultado,
conforme detalhado abaixo:


Passo a passo para listar mais de 50 registros

O campo de controle para consulta é o, que é demonstrado no retorno da consulta. Para retorno com
mais de 50 registros o campo retorna “S” e quando existe menos de 50 registro retorna “N”, conforme
Layout de Comunicação – Retorno.
Quando o campo apresentar resultado “N” é porque não existem mais informações a serem retornadas
e que a consulta está completa.

Caso retorne “S”, significa que existem mais registros a serem demonstrados. Para listar as demais
informações, basta programar para que seja repetida a chamada realizada anteriormente, adicionando
no campo Layout de Comunicação Entrada o valor retornado no campo Layout de Comunicação
retorno. (“ACBrBoleto Bradesco API, Consulta em Lista para Boletos Híbridos ...”)

Obs.: Essa ação deverá ser repetida sucessivamente, até que o campo” seja igual a “N", o que significa
que todos os registros que atendem ao critério foram demonstrados e a consulta está completa.


Exemplo:

Existem 140 registros que atendem à consulta.

•     Na primeira chamada o campo deve ser igual a 0
•     O retorno irá demonstrar os 50 primeiros registros, o campo igual a “1” e o campo igual a “S”
•     Como o campo é igual a “S”, deverá ser efetuada novamente a mesma chamada, porém incluindo no
      campo a informação retornada no campo, que neste caso será igual a "1”.
•     Então, serão retornados os próximos 50 registros, o campo será igual a “2” e o campo igual a “S”
      (“ACBrBoleto Bradesco API, Consulta em Lista para Boletos Híbridos ...”)
•     Como o campo é igual a “S”, deverá ser efetuada novamente a mesma chamada, porém informando
      o campo com a nova informação retornada no campo, que neste caso será "2”.
•     Então serão retornados mais 40 registros, o campo será igual a “3” e campo igual a “N”
•     Como foi retornado “N” no campo, significa que todos os registros da consulta foram demonstrados,
      neste exemplo os 140 registros, portanto a consulta está completa.

Consulta Split Payment (Rateio de Crédito)
 A API Consulta Split Payment (Rateio de Crédito) oferece uma forma prática e segura de acessar os
 detalhes do rateio de crédito aplicado a um título, proporcionando mais transparência e controle sobre
 os valores distribuídos entre os beneficiários.


 Com essa API, você pode consultar:

 • O número do título vinculado ao Split;
 • Os dados dos beneficiários envolvidos;
 • Os valores rateados para cada participante;
 • O status atual da operação de Split.


 A consulta é realizada por meio do envio de uma requisição com os dados do título, e a API retorna as
 informações consolidadas, garantindo confiabilidade e agilidade no acesso aos dados.



  Ambiente         Método          URL



  Sandbox          POST            https://openapisandbox.prebanco.com.br/boleto/cobranca-consulta-split/v1/executar

Consulta lista de título pendente
A API de Consulta de Títulos Pendentes permite consultar os títulos de cobrança ativos, oferecendo
uma visão atualizada das pendências em aberto.

Essa funcionalidade proporciona maior controle e eficiência na gestão da carteira de cobrança,
apoiando o acompanhamento dos recebíveis e a tomada de decisões.

Para realizar a consulta, é necessário informar os campos obrigatórios do título:

•     CPF/CNPJ do Beneficiário
•     Negociação
•     Produto (Carteira)

Além dos campos obrigatórios, podem ser informados parâmetros adicionais, de forma que sejam
retornados apenas os títulos que atendam aos critérios definidos.

Parâmetros disponíveis para pesquisa

•     Nosso Número (opcional)
•     CPF/CNPJ do Pagador (opcional)
•     Data de Vencimento – período De/Até (opcional)
•     Data de Registro – período De/Até (opcional)
•     Valor – a partir de um valor mínimo informado (opcional)

É possível realizar a combinação de múltiplos critérios de consulta. Por exemplo, consultar os títulos
de um determinado CPF/CNPJ, dentro de uma faixa de vencimento e a partir de um valor específico.

Quanto maior o número de critérios informados, mais refinado será o resultado da consulta. As
informações disponibilizadas seguem o critério D-1 (dados do dia anterior).

A consulta retorna até 50 registros por chamada. Caso existam mais registros, é possível realizar
chamadas recorrentes para obter a totalidade dos resultados.

PASSO A PASSO PARA LISTAR MAIS DE 50 REGISTROS


O campo de controle para consulta é o, que é demonstrado no retorno da consulta. Para retorno com
mais de 50 registros o campo retorna “S” e quando existe menos de 50 registro retorna “N”, conforme
Layout de Comunicação – Retorno.

Se o campo apresentar resultado “N” é porque não existem mais informações a serem retornadas e
que a consulta está completa.

Caso retorne “S”, significa que existem mais registros a serem demonstrados.
Para acessar as demais informações, basta programar para que seja repetida a chamada realizada
anteriormente, adicionando no campo o conteúdo demonstrado no retorno da consulta no campo.


Obs.: Essa ação deverá ser repetida sucessivamente, até que o campo” seja igual a “N”, o que significa
que todos os registros que atendem ao critério foram demonstrados e a consulta está completa.

Consulta lista de títulos baixados
A funcionalidade permite a consulta, via API, dos títulos de cobrança baixados, proporcionando
maior controle e eficiência na gestão da carteira de Cobrança.

Para realizar a consulta, é necessário informar os campos obrigatórios do título:

•       CPF/CNPJ do Beneficiário
•       Negociação
•       Produto (Carteira)

Além dos campos obrigatórios, podem ser informados parâmetros adicionais, de modo que sejam
retornados apenas os títulos que atendam aos critérios definidos.

É possível realizar a combinação de múltiplos critérios de consulta. Por exemplo, consultar os títulos
de um determinado CPF/CNPJ, associados a uma carteira específica, dentro de uma faixa de datas de
vencimento.
Quanto maior o número de critérios informados, mais refinado será o resultado da consulta. As
informações disponibilizadas seguem o critério D-1 (dados do dia anterior).

A consulta retorna até 50 registros por chamada. Caso existam mais registros, é possível realizar
chamadas recorrentes para obter a totalidade dos resultados.


    Ambiente          Método                URL

    Sandbox           POST                  https://openapisandbox.prebanco.com.br/boleto/cobranca-baixado-consulta/v1/listar

    Produção          POST                  **https://openapi.bradesco.com.br/boleto/cobranca-baixado-consulta/v1/listar

Obs.: A consulta demonstra até 50 registros por chamada. Porém, se a consulta possuir mais registros,
é necessário programar chamadas recorrentes para demonstrar todo o resultado, conforme
detalhado abaixo:


PASSO A PASSO PARA LISTAR MAIS DE 50 REGISTROS


O campo de controle para consulta é o, que é demonstrado no retorno da consulta. Para retorno com
mais de 50 registros o campo retorna “S” e quando existe menos de 50 registro retorna “N”, conforme
Layout de Comunicação – Retorno.

Se o campo apresentar resultado “N” é porque não existem mais informações a serem retornadas e
que a consulta está completa.

Caso retorne “S”, significa que existem mais registros a serem demonstrados.

Para acessar as demais informações, basta programar para que seja repetida a chamada realizada
anteriormente, adicionando no campo o conteúdo demonstrado no retorno da consulta no campo.

Obs.: Essa ação deverá ser repetida sucessivamente, até que o campo” seja igual a “N”, o que significa
que todos os registros que atendem ao critério foram demonstrados e a consulta está completa.

WEBHOOK
O webhook é uma maneira de um aplicativo fornecer informações em tempo real para outros aplicativos.

Ele envia dados automaticamente para um URL específico quando um evento de pagamento ocorrer, sem
a necessidade de solicitações contínuas.

É muito útil para integrações e automações, permitindo que sistemas diferentes se comuniquem de forma
eficiente.


Como realizar o cadastro do cliente para uso do Webhook
Para utilização do webhook de cobrança, é necessário primeiramente realizar o cadastro. Para isso, basta
enviar os dados da empresa (CNPJ, endereços URLs e token) e informar o tipo de cadastro = “i” (inclusão),
nos parâmetros de entrada.

É possível também realizar Alteração, Exclusão e Consulta do cadastro.

Com o envio das informações preenchidas corretamente, o cadastro será realizado com sucesso, sendo
retornadas, na sequência, as informações cadastradas.



     Ambiente         Método                   URL


                                               https://openapisandbox.prebanco.com.br/boleto/cobranca-
     Sandbox          POST
                                               webhook/v1/cadastrar


     Produção         POST                    https://openapi.bradesco.com.br/boleto/cobranca-   webhook/v1/executar
Qual o modelo de certificado digital do cliente para utilizar o webhook

Em caso de callback via webhook, a premissa é que o certificado deverá:

   •   Ser emitido por uma Autoridade Certificadora (AC) amplamente reconhecida pelos navegadores e
       clientes do mercado

   •   Conter no campo CN (Common Name) a URL do ambiente no qual será hospedado.

   •   Possuir validade mínima de 1 ano.


O certificado deverá ser do tipo SSL, modelo EV (Extended Validation) ou OV (Organization Validation).
O modelo DV (Domain Validation) não é aceito, pois não válida a empresa, apenas o domínio na internet.


O cliente deve enviar o seu certificado público, zipado, do tipo SSL de webhook da cobrança, para o
e-mail: governancaapis@bradesco.com.br solicitando o cadastro.




Além disso, é necessário também configurar o certificado do Bradesco como confiável em sua aplicação.

Para baixar o certificado do Bradesco, acesse a página CERTIFICADOS no menu Inicial do Portal Bradesco
Developers.




Somente após a conclusão de todo o fluxo de cadastro do Certificado Digital (SLA: até 5 dias úteis), o
cliente passará a receber as notificações dos pagamentos realizados nos seus títulos de cobrança,
conforme o layout de Notificação de Pagamentos.

Notificação Dos Pagamentos (Webhook)

Após concluir o cadastramento, o cliente passará a receber as notificações, de forma automática, dos
pagamentos realizados nos seus títulos de cobrança pelo endereço cadastrado.

Para os pagamentos de boletos convencionais, pagos via código de barras, o envio das informações será
on-line*. Para os pagamentos do boleto híbrido, pagos via QR Code, o envio das informações será em até
20 minutos.

Caso o pagamento não seja efetivado por alguma razão, o cliente não receberá nenhuma notificação. Para
receber as notificações, deve ter sido preparado o layout, conforme descrito abaixo:

        FAQ

     Qual o tempo médio entre a solicitação de registro do boleto e a efetivação do registro na CIP?

     O registro ocorre na CIP em 1 segundo.


     Se, por algum motivo, o serviço on-line fique indisponível por tempo indeterminado ou por
     elevado tempo impedindo o registro da cobrança, temos alguma contingência por parte do
     Bradesco?

     Sim, Através do NET EMPRESA.


     No campo “nuCliente” que informação devo passar?

     Essa informação é de responsabilidade do cliente, não é consistida pelo banco, é o equivalente a “Seu
     Número”, normalmente utilizada para informar o número da nota fiscal.


     É possível a emissão de segunda via do boleto on-line?

     A API disponibiliza a funcionalidade de consultar um título em específico de forma detalhada e
     atualizada para a consulta gerencial e/ou geração 2ª. via de boleto.
No campo “nuTitulo” que informação devo passar?

Essa informação é a Identificação do título para o banco (NOSSO NÚMERO), pode ser informado pelo
cliente ou gerado pelo banco, esse número deve ser único de acordo com a carteira e negociação
utilizada.


É possível cadastrar informações de cobrança de juros e Multa no convênio de cobrança de
forma fixa?

Não, para os registros de títulos de forma online, só é acatado as informações de Juros e Multa
informados no registro do boleto através da API, ele não carrega a informação do convênio.


Como informar Juros e Multa no registro de boleto via API de Cobrança?

“percentualJuros” –Para 10% informe “10000,”;
“vlJuros” –Para R$1,00 informe “100,”;
"qtdeDiasJuros “–Para 1 dia informe “1,”;
“percentualMulta” -Para 10% informe “10000”.



Como incluir protesto automático e negativação no registro de um boleto via Api de Registro de
Cobrança?

É necessário informar a quantidade de dias no campo “prazoProtestoAutomáticoNegativação”
Para Protesto na condição de dias úteis: 3 dias após o vencimento. Dias corridos 5 dias após
vencimento.
Para Negativação informar a quantidade de dias, considerar 5 dias corridos após o vencimento.


O serviço de cadastrar no Webhook utiliza SOAP ou REST?

Utiliza REST.


Qual o tempo, após o boleto ser pago, serei notificado?

Pagamentos realizados utilizando o código de barras: on-line*.
Pagamentos realizados utilizando o Qr Code: até 20 minutos.

•   As notificações de pagamentos realizados em outros bancos serão encaminhadas imediatamente
    após o envio da informação por parte do banco recebedor ao Bradesco.


É possível o Split de um título registrado com valor zero?

Sim, mas para execução dessa operação o rateio será sobre o valor cobrado, em percentual.


O valor/percentual pode ser informado com zero ou em branco?

Não, caso contrário será desconsiderado o registro do Split para o beneficiário informado. É
importante se atentar ao preenchimento do campo, de acordo com o cálculo do Split e o tipo de valor:

Moeda Corrente - Deverá ser informada com 2 (duas) decimais;
• Exemplo: 2300,00 => 230000
Moeda Indexada - Deverá ser informada com 5 (cinco) decimais.
• Exemplo: 2300,00000 => 230000000

Percentual - Deverá ser informado com 3 (três) decimais.
• Exemplo: 50% => 50000


Como devo preencher o campo de parcela de rateio de crédito?

O campo é para uso do cliente, portanto, a definição do preenchimento cabe a este, limitado ao
tamanho do campo. Exemplos:

•   1/3;
•   1 de 3.


Quantos beneficiários posso incluir em rateio para um título?

Para cada título são permitidos até noventa (90) beneficiários, incluídos dez (10) beneficiários a cada
execução da API. É importante ressaltar que caso o total do valor ou percentual informado ultrapasse
o total disponível para rateio, a solicitação será recusada, sendo incluso/alterados os beneficiários que
não ultrapassem o limite de valor ou percentual. Os demais serão recusados na execução.
Posso efetuar mais de uma ação de rateio por execução?

Não, cada execução deve ser orientada para uma única ação, sendo a primeira reconhecida na lista
como a ação desejada. Qualquer outra ação encontrada na lista, divergente da primeira, será
descartada na execução.
